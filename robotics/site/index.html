Robotics and Arduino

نظرة عامة

يتعرّف المتعلّم إلى النظام الروبوتي بوصفه ترابطاً بين الاستشعار والمعالجة والتنفيذ، ويجهّز Arduino UNO R3 ثم يرفع أول Sketch للتحقّق من بيئة العمل.

أهداف التعلّم

• تصنيف Sensor وController وActuator في مثال واقعي.

• تحديد USB وDigital Pins و5V وGND على Arduino UNO R3.

• اختيار Board وPort ورفع Sketch وقراءة رسالة في Serial Monitor.

المفاهيم التقنية

Robotics • Microcontroller • Arduino UNO R3 • Sketch • setup() • loop() • Verify • Upload

• Arduino UNO R3 المبني على ATmega328P

• USB Data Cable متوافق مع اللوحة

• حاسوب وArduino IDE 2

الشرح النظري

يستقبل Sensor معلومة عن البيئة، وينفّذ Microcontroller تعليمات لمعالجتها، ثم يوجّه Actuator. لا تتحول كل دائرة LED إلى Robot؛ لكنها تبني مهارات التحكم اللازمة. تنفّذ setup() مرة عند البدء، وتتكرر loop(). نستخدم LED_BUILTIN المثبّت على اللوحة للتحقّق دون توصيل خارجي.

التجربة العملية والتوصيل

1 افصل أي دوائر خارجية واترك Arduino UNO R3 وحده.

2 صل USB Data Cable بالحاسوب واللوحة؛ لا توصل مصدر طاقة خارجياً.

التنفيذ خطوة بخطوة

1 ثبّت Arduino IDE 2 من المصدر الرسمي واتبع دليل الإعداد في الملحق.

2 اختر Arduino AVR Boards ثم Arduino UNO وPort الفعلي.

3 افتح Lesson01.ino وشغّل Verify ثم Upload.

4 افتح Serial Monitor على 9600 واضغط Reset إذا أردت رؤية رسالة البدء مجدداً.

5 راقب LED_BUILTIN وحدّد أي تعليمة تغيّر حالته.

Arduino Code

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.begin(9600);
  Serial.println("Arduino ready");
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(500);
  digitalWrite(LED_BUILTIN, LOW);
  delay(500);
}

شرح Code

• pinMode() يهيّئ LED_BUILTIN بوصفه OUTPUT.

• Serial.begin(9600) يحدد Baud Rate.

• digitalWrite() يبدّل HIGH وLOW، وdelay() يوقف التنفيذ مؤقتاً.

النتيجة المتوقعة

تظهر Arduino ready عند Reset ويومض LED_BUILTIN. ظهور رسالة Upload الناجحة مع الوميض دليل تشغيل أولي، وليس اختباراً لجميع Pins.

تحدٍّ إضافي

غيّر قيمتي delay() لتجعل الوميض غير متناظر، وتوقّع النتيجة قبل Upload.

أسئلة التقييم

1 ما الفرق بين setup() وloop()؟

2 لماذا قد يظهر Power LED مع تعذّر Upload؟

مفتاح الإجابات للمدرّب

1 setup() للتهيئة مرة واحدة وloop() للتكرار.

2 Power LED يثبت وصول الطاقة فقط؛ قد يكون الكابل للشحن أو Board/Port خاطئاً.

3 Sensor يقيس، وActuator ينفّذ أثراً مثل الحركة.

LED Control

نظرة عامة

أهداف التعلّم

• توصيل LED مع Resistor على التوالي دون Short Circuit.

• استخدام pinMode() وdigitalWrite() بصورة صحيحة.

• ربط HIGH وLOW بحالة LED في التوصيل المعتمد.

المفاهيم التقنية

Digital Output • HIGH • LOW • Resistor • Polarity • Current • Voltage • const byte

المكوّنات المطلوبة

• عدة الدرس الأول

• Red LED واحد

• Resistor بقيمة 330 Ω

• Breadboard وJumper Wires

الشرح النظري

يسمح LED بمرور Current باتجاه محدد ويحتاج إلى Resistor لتقييد Current. في هذا التوصيل يضيء عندما يصبح D2 عند HIGH ويطفأ عند LOW. تمثّل HIGH مستوى منطقياً قريباً من جهد تشغيل اللوحة، وليست أمراً بضخ Current بلا حدود. عند LED أحمر بجهد أمامي تقريبي 2V، يعطي 330 Ω تياراً تقريبياً قدره 9mA؛ تختلف القيمة الفعلية باختلاف LED.

التجربة العملية والتوصيل

1 افصل USB قبل التوصيل.

2 صل D2 إلى Resistor بقيمة 330 Ω ثم إلى Anode في Red LED.

3 صل Cathode إلى GND. الطرف الطويل غالباً Anode والحافة المسطّحة غالباً Cathode؛ تحقّق من المكوّن.

4 لا تصل LED مباشرة بين 5V وGND ولا تتجاوز Resistor.

التنفيذ خطوة بخطوة

1 حدّد صفوف Breadboard باستخدام مخططها.

2 ابنِ التوصيل وافحص مسار D2 → Resistor → LED → GND.

3 افتح Lesson02.ino وتوقّع سلوك الوميض.

4 شغّل Verify ثم Upload بعد مراجعة المدرّب.

5 عدّل قيمة واحدة في delay() وسجّل الفرق.

Arduino Code

const byte LED_PIN = 2;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(1000);
  digitalWrite(LED_PIN, LOW);
  delay(1000);
}

شرح Code

• LED_PIN اسم ثابت يربط Code بالتوصيل D2.

• pinMode(LED_PIN, OUTPUT) يضبط اتجاه Pin.

• كل digitalWrite() تتبعها delay() لإظهار الحالة قبل الانتقال.

النتيجة المتوقعة

يضيء Red LED وينطفئ بالتناوب. عند عكس HIGH وLOW في Code يتبدّل ترتيب الحالتين فقط.

نظرة عامة

الشرح النظري

4 استخدم GND مشتركاً وResistor منفصلاً لكل LED.

3 افتح Lesson03.ino وتتبع أول دورة على الورق.

4 ارفع Sketch وسجّل ترتيب الإضاءة والإطفاء.

5 احذف تعليمة إطفاء في نسخة تجريبية، وتنبّأ بالتداخل ثم أعدها.

const byte RED_PIN = 2;
const byte YELLOW_PIN = 3;
const byte GREEN_PIN = 4;

void setup() {

  delay(3000);
  digitalWrite(RED_PIN, LOW);
  digitalWrite(GREEN_PIN, HIGH);
  delay(3000);
  digitalWrite(GREEN_PIN, LOW);
  digitalWrite(YELLOW_PIN, HIGH);
  delay(1000);
  digitalWrite(YELLOW_PIN, LOW);

• ثلاث Constants تمنع الخلط بين Pins.

• تستمر حلقة التسلسل دون Arrays أو Libraries إضافية.

Push Button Control

نظرة عامة

يستخدم الطالب Push Button كـ Digital Input ويضيء LED أثناء الضغط، مستفيداً من INPUT_PULLUP لمنع Input العائم.

أهداف التعلّم

• توصيل Push Button بين D7 وGND باستخدام INPUT_PULLUP.

• تفسير أن الضغط يعطي LOW في هذا التوصيل.

• تطبيق Condition للتحكّم في LED دون تغيير الدائرة.

المفاهيم التقنية

Digital Input • INPUT_PULLUP • digitalRead() • Boolean • Condition • Floating Input

المكوّنات المطلوبة

• Arduino UNO R3 وUSB وBreadboard

• Red LED و330 Ω

• Push Button لحظي وJumper Wires

الشرح النظري

يحافظ INPUT_PULLUP على D7 عند HIGH عندما يكون الزر مفتوحاً. عند الضغط يتصل D7 بـ GND فتكون القراءة LOW. كثير من Push Buttons ذات أربعة أطراف تضم طرفين متصلين داخلياً في كل جانب؛ اختر طرفاً من كل مجموعتين متقابلتين، أو تحقّق باستخدام Continuity Test والطاقة مفصولة. لا يحوّل هذا المثال الضغط إلى Toggle؛ فالضوء يتبع حالة الضغط فقط.

التجربة العملية والتوصيل

1 أبقِ Red LED على D2 مع 330 Ω وGND كما في الدرس الثاني.

2 صل D7 بأحد طرفي Push Button وGND بالطرف المقابل الذي يتصل به عند الضغط.

3 لا توصل الزر بين 5V وGND مباشرة، ولا تضف Pull-down Resistor إلى هذا المثال.

التنفيذ خطوة بخطوة

1 افصل الطاقة وتحقّق من مجموعتي أطراف Push Button.

2 حمّل Lesson04.ino واقرأ Condition قبل التشغيل.

3 اختبر حالتي الضغط والإفلات عدة مرات.

4 غيّر LED_PIN في Code فقط لملاحظة أثر عدم تطابق التوصيل، ثم أعده.

5 اشرح لزميل لماذا يعني LOW أن الزر مضغوط.

Arduino Code

const byte LED_PIN = 2;
const byte BUTTON_PIN = 7;

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
}

void loop() {
  bool pressed = digitalRead(BUTTON_PIN) == LOW;
  digitalWrite(LED_PIN, pressed ? HIGH : LOW);
}

شرح Code

• pressed يخزّن نتيجة مقارنة القراءة بـ LOW.

• المعامل الشرطي ? : يختار HIGH أو LOW؛ يمكن استبداله بـ if/else مكافئ.

• لا نحتاج Debounce لهذا العرض المستمر البسيط؛ نحتاجه عند عدّ الضغطات أو Toggle.

النتيجة المتوقعة

يضيء Red LED أثناء الضغط ويطفأ عند الإفلات. لا تُخزّن حالة تشغيل بين الضغطات.

Ultrasonic Distance Sensor

نظرة عامة

المفاهيم التقنية

HC-SR04 • Ultrasonic Sensor • Trigger • Echo • pulseIn() • Timeout • Serial Monitor • float

• Jumper Wires ومسطرة ولوح مسطّح

الشرح النظري

1 افصل الطاقة واقرأ أسماء Pins المطبوعة؛ لا تفترض ترتيباً اعتماداً على لون السلك.

2 VCC إلى 5V وGND إلى GND.

3 Trig إلى D10 وEcho إلى D11 على Arduino UNO R3 ذي منطق 5V.

4 لا تعمم هذا التوصيل على لوحات 3.3V؛ قد تحتاج Echo إلى Level Shifting.

التنفيذ خطوة بخطوة

Arduino Code

const byte TRIG_PIN = 10;
const byte ECHO_PIN = 11;

float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);
  unsigned long durationUs = pulseIn(ECHO_PIN, HIGH, 25000UL);
  if (durationUs == 0) return -1.0;
  float distanceCm = durationUs * 0.0343 / 2.0;
  if (distanceCm < 2.0 || distanceCm > 400.0) return -1.0;
  return distanceCm;
}

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  Serial.begin(9600);
}

void loop() {
  float distanceCm = readDistanceCm();
  if (distanceCm < 0) {
    Serial.println("No valid reading");
  } else {
    Serial.print("Distance cm: ");
    Serial.println(distanceCm, 1);
  }
  delay(70);
}

شرح Code

• Trigger يرتفع 10µs ثم ينخفض.

• pulseIn(..., 25000UL) يحد الانتظار تقريباً إلى 25ms لكل محاولة، ويظل Blocking أثناءها.

• تُعاد −1 عند Timeout أو الخروج من المجال، وتفصل delay(70) بين المحاولات.

الشرح النظري

Automatic Garage Gate

نظرة عامة

يدمج الطالب HC-SR04 وServo مع Boolean State وHysteresis وانتظار خلو قصير يمنع تذبذب البوابة بسبب قراءة قرب الحد.

أهداف التعلّم

• فتح البوابة عند اقتراب هدف ضمن 15 cm.

• الإغلاق فقط بعد قراءة ≥25 cm مستمرة، دون استخدام delay() طويل للانتظار.

• تفسير إبقاء البوابة مفتوحة عند Invalid وإعادة بدء انتظار الخلو.

المفاهيم التقنية

Integration • Boolean State • Hysteresis • millis() • Elapsed Time • Timeout

المكوّنات المطلوبة

• عدة HC-SR04

• Position Servo ومصدر 5V خارجي وGND مشترك

• قاعدة كرتونية وذراع ورقي خفيف وسيارة لعبة أو لوح هدف

الشرح النظري

تُستخدم عتبة للفتح وأخرى للخلو: ≤15 cm تفتح، و≥25 cm تبدأ انتظار الخلو، والمنطقة بينهما تبقي الحالة وتلغي انتظار الإغلاق. يقارن millis() زمناً حالياً بـ clearSince باستخدام unsigned long. إذا أصبحت القراءة Invalid تُفتح البوابة ويبطل الانتظار؛ هذا اختيار تعليمي لتجنّب إغلاق النموذج اعتماداً على قراءة مجهولة، وليس نظام أمان معتمداً. تؤخذ القياسات دورياً مع Blocking محدود داخل pulseIn().

التجربة العملية والتوصيل

1 أبقِ HC-SR04 على D10/D11 و5V/GND.

2 Servo Signal إلى D9، وتغذيته من 5V الخارجي كما في الدرس الثامن مع Common Ground.

3 ثبّت Sensor ليرى السيارة قبل الذراع؛ لا تجعله يقرأ الذراع نفسه.

4 اختبر دون ذراع أولاً، ثم استخدم ورقاً خفيفاً بعد فصل الطاقة.

التنفيذ خطوة بخطوة

1 اختبر Sensor وServo منفصلين بملفي الدرسين السادس والثامن.

2 افتح Lesson09.ino وتتبّع gateOpen وclearTiming.

3 ضع هدفاً عند 10 cm للتحقّق من الفتح.

4 انقله إلى 20 cm: يجب أن يبقى مفتوحاً دون إغلاق.

5 انقله إلى 30 cm وأبقِ قياسات صالحة؛ يغلق بعد انتظار الخلو.

6 أزل الهدف أو احجب القياس: عند Invalid يفتح ويلغى انتظار الخلو.

Arduino Code

#include <Servo.h>

const byte TRIG_PIN = 10;
const byte ECHO_PIN = 11;

float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);
  unsigned long durationUs = pulseIn(ECHO_PIN, HIGH, 25000UL);
  if (durationUs == 0) return -1.0;
  float distanceCm = durationUs * 0.0343 / 2.0;
  if (distanceCm < 2.0 || distanceCm > 400.0) return -1.0;
  return distanceCm;
}

Servo gate;
const byte SERVO_PIN = 9;
const int CLOSED_ANGLE = 20;
const int OPEN_ANGLE = 90;
bool gateOpen = false;
bool clearTiming = false;
unsigned long clearSince = 0;

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  gate.attach(SERVO_PIN);
  gate.write(CLOSED_ANGLE);
}

void loop() {
  float distanceCm = readDistanceCm();
  unsigned long now = millis();
  if (distanceCm < 0 || distanceCm <= 15) {
    gateOpen = true;
    clearTiming = false;
  } else if (gateOpen && distanceCm >= 25) {
    if (!clearTiming) {
      clearSince = now;
      clearTiming = true;
    }
    if (now - clearSince >= 2000UL) gateOpen = false;
  } else {
    clearTiming = false;
  }
  gate.write(gateOpen ? OPEN_ANGLE : CLOSED_ANGLE);
  delay(70);
}

شرح Code

• gateOpen يخزّن حالة البوابة، وclearTiming يحدد وجود انتظار نشط.

• now - clearSince مقارنة آمنة ضمن حدود فترات قصيرة مع unsigned long.

• delay(70) هنا فترة أخذ العينات؛ لا تعني أن البرنامج خالٍ تماماً من Blocking.

• تبدأ Lesson09 بأمر Closed في setup()، ثم تعمل قواعد الفتح والخلو. في Lesson10 يتغير بدء التشغيل عمداً إلى Open حتى يتوفر قياس خلو صالح؛ لا تخلط بين تهيئة المثالين.

المشروع نموذج مدخل موقف، ولا يحسب عدد المواقف الشاغرة أو اتجاه عبور السيارة؛ ذلك يتطلب استشعاراً ومنطقاً إضافيين. يبدأ Open حتى يتأكد من خلو صالح. Green يعني أمراً بالفتح مع قياس صالح، وRed أمراً بالإغلاق، وYellow قراءة غير صالحة. تومض لا تُفترض؛ LEDs ثابتة حسب الحالة. يصدر Buzzer نبضة عند انتقال صحيح فقط، ويصمت عند Invalid. ضغط Push Button يبقي الفتح ولا يفرض الإغلاق. لا تؤكد LEDs موضع الذراع الحقيقي لعدم وجود Feedback Sensor.

التجربة العملية والتوصيل

1 استخدم خريطة التوصيلات الموحدة في قسم المشروع النهائي؛ لا تغيّر أرقام Pins.

2 راجع توصيلات HC-SR04 وLEDs وBuzzer وPush Button قبل إضافة Servo.

3 غذِّ Servo خارجياً مع Common Ground؛ لا تربط خطي +5V ببعضهما.

4 ضع Sensor بحيث يرى هدفاً أو خلفية صالحة بعيداً عن الذراع، وثبّت الأسلاك خارج الحركة.

Arduino Code

#include <Servo.h>

const byte TRIG_PIN = 10;
const byte ECHO_PIN = 11;

float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);
  unsigned long durationUs = pulseIn(ECHO_PIN, HIGH, 25000UL);
  if (durationUs == 0) return -1.0;
  float distanceCm = durationUs * 0.0343 / 2.0;
  if (distanceCm < 2.0 || distanceCm > 400.0) return -1.0;
  return distanceCm;
}

Servo gate;
const byte RED_PIN = 2;
const byte YELLOW_PIN = 3;
const byte GREEN_PIN = 4;
const byte BUTTON_PIN = 7;
const byte BUZZER_PIN = 8;
const byte SERVO_PIN = 9;
const int CLOSED_ANGLE = 20;
const int OPEN_ANGLE = 90;
bool gateOpen = false;
bool clearTiming = false;
unsigned long clearSince = 0;
unsigned long lastSample = 0;

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  pinMode(RED_PIN, OUTPUT);
  pinMode(YELLOW_PIN, OUTPUT);
  pinMode(GREEN_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(BUZZER_PIN, OUTPUT);
  Serial.begin(9600);
  gate.attach(SERVO_PIN);
  gate.write(OPEN_ANGLE);
  gateOpen = true;
}

void loop() {
  unsigned long now = millis();
  if (now - lastSample < 70UL) return;
  lastSample = now;
  float distanceCm = readDistanceCm();
  bool valid = distanceCm >= 0;
  bool manualOpen = digitalRead(BUTTON_PIN) == LOW;
  bool previousOpen = gateOpen;

  if (!valid || manualOpen || distanceCm <= 15) {
    gateOpen = true;
    clearTiming = false;
  } else if (gateOpen && distanceCm >= 25) {
    if (!clearTiming) {
      clearSince = now;
      clearTiming = true;
    }
    if (now - clearSince >= 2000UL) gateOpen = false;
  } else {
    clearTiming = false;
  }

  gate.write(gateOpen ? OPEN_ANGLE : CLOSED_ANGLE);
  digitalWrite(RED_PIN, !gateOpen && valid);
  digitalWrite(GREEN_PIN, gateOpen && valid);
  digitalWrite(YELLOW_PIN, !valid);
  if (previousOpen != gateOpen && valid) {
    tone(BUZZER_PIN, gateOpen ? 1200 : 700, 120);
  }
  if (!valid) {
    noTone(BUZZER_PIN);
    Serial.println("Sensor fault: gate open");
  } else {
    Serial.print(distanceCm, 1);
    Serial.println(gateOpen ? " cm OPEN" : " cm CLOSED");
  }
}

شرح Code

• lastSample يحدد بداية محاولة جديدة كل 70ms على الأقل دون delay() عام.

• pulseIn() يبقى Blocking محدوداً بـ Timeout؛ لا نصف النظام بأنه Non-blocking بالكامل.

• previousOpen يمنع تكرار نبضة Buzzer دون انتقال.

• يُعاد ضبط clearTiming عند Near أو Manual Open أو Invalid، ولذلك يلزم خلو متصل قبل الإغلاق.

System Architecture

HC-SR04 وPush Button → قراءة Input والتحقق من valid → Conditions وBoolean State مع Hysteresis وانتظار Clear → Servo Command وLEDs وTone. يعمل Arduino عبر USB، ويعمل Servo من 5V خارجي؛ يلتقي المصدران في GND فقط. تستخدم Serial Monitor للملاحظة وليست واجهة تحكّم بالمشروع.

قواعد السلامة الأساسية

• استخدم DC منخفض الجهد فقط. يجهّز المدرّب مصادر الطاقة؛ لا يفتح الطلاب محوّلات أو أجهزة Mains ولا يتعاملون مع أسلاكها.

• افصل USB ومصدر Servo قبل إضافة الأسلاك أو نقلها. افحص Polarity و5V وGND وصفوف Breadboard قبل إعادة التغذية.

• ضع Resistor مستقلاً 330 Ω لكل LED. لا توصل 5V إلى GND ولا تستخدم Pin كخط تغذية لـ Motor أو حمل مرتفع التيار.

• في أمثلة Servo: مصدر خارجي منظّم 5V ملائم للمكوّن مع Common Ground، وArduino عبر USB. لا تربط خطي الموجب معاً ولا تفترض أن USB يستطيع تغذية Servo تحت حمل.

• عند ارتفاع حرارة أو رائحة أو Reset متكرر افصل التغذية أولاً، ثم افحص الدائرة دون لمس المكوّن الساخن. لا تعالج المشكلة بإعادة التشغيل المتكرر.

• استخدم Passive Piezo محدد المواصفات ومنخفض التيار. لا تستبدله بمكبّر صوت أو Buzzer مغناطيسي دون Driver مناسب خارج النطاق.

• جرّب Servo دون ذراع ثم بذراع ورقي خفيف. أبعد الأصابع والأسلاك عن الحركة ولا تدفع الذراع بالقوة أو تثبته عند Stall.

• لا يستخدم نموذج البوابة للتحكّم في مرور أشخاص أو مركبات حقيقية. Ultrasonic Sensor واحد ليس Safety Interlock ولا يضمن كشف كل جسم.

• راعِ الصوت والاحتياجات السمعية، ووفّر بديلاً بصرياً. تجنّب الوميض المزعج والأصوات العالية.

• راجع مواصفات النسخة الفعلية من Sensor وServo وPinout؛ لا تعتمد على لون الأسلاك أو تشابه الشكل وحده.

توجد ثلاثة أسئلة ومفتاح إجابة خاص بالمدرّب في كل درس، بإجمالي 30 سؤالاً. تُطرح شفهياً أو كتابياً قبل تحدٍّ إضافي؛ وعند الخطأ يطلب المدرّب الدليل من Circuit أوCode ثم يعيد السؤال بصياغة تطبيقية.

قائمة تحضير المدرّب

• اختبار كامل للمجموعة المرجعية ومطابقة Pins مع ملفات .ino، والتحقّق من إصدارات Board Package وServo.

• فحص USB Data Cables والتعريفات وBoard/Port وتثبيت البرامج مسبقاً.

• عدّ المكوّنات وتجهيز قطع بديلة وملصقات Polarity ومصادر DC آمنة.

• تجربة Servo بلا حمل والتحقّق من Current ومجال الزوايا وقدرة المصدر.

• إعداد Background صالح لـ HC-SR04 واختبار حالات Near وFar وInvalid.

• تجهيز أوراق العمل وتحديد الأدوار وتكييف العرض للمتعلمين ذوي احتياجات بصرية أو سمعية.

• تحديد نقطة فحص قبل الطاقة ونقطة فحص قبل تركيب الذراع، وإيقاف أي نموذج يسخن أو يعيد التشغيل.

• تجهيز أسئلة تشخيص متنوعة ونسخة Code ناقصة جزئياً للدعم وتحدٍّ إضافيs للمتقدمين.

• إظهار خطأ واحد مقصود يمكن إصلاحه دون مخاطرة، مثل Pin غير مطابق، لا Short Circuit حي.

• حفظ أدلة التعلّم بأسماء الدروس، ومراجعة ما لم يتحقق قبل الانتقال.
